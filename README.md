## Overview

This project implements a Deep Q-Network (DQN) agent to play Atari Breakout.
The agent learns action values from stacks of four preprocessed grayscale
frames. Training uses experience replay, a separate target network, and an
epsilon-greedy exploration policy.

The completed training run reached **3,000,000 agent steps** and saved its
checkpoint as `dqn.pth`. Evaluation of that checkpoint completed **100 episodes
with five lives per episode**, achieving a **mean reward of 280.55**. This exceeds
the assignment's stated target of a mean reward above 40.

## Network Architecture

The implementation uses the following baseline architecture:

| Layer | Configuration | Output shape, excluding batch dimension |
|---|---|---|
| Input | Four stacked 84 × 84 grayscale frames | `4 × 84 × 84` |
| Convolution + ReLU | 32 filters, kernel 8 × 8, stride 4 | `32 × 20 × 20` |
| Convolution + ReLU | 64 filters, kernel 4 × 4, stride 2 | `64 × 9 × 9` |
| Convolution + ReLU | 64 filters, kernel 3 × 3, stride 1 | `64 × 7 × 7` |
| Flatten | — | `3136` |
| Fully connected + ReLU | 512 units | `512` |
| Output | One Q value per action | `4` |

Observations are converted from `(84, 84, 4)` to channel-first tensors. Pixel
values are divided by 255 inside the network. The output has no softmax because
it represents action values rather than probabilities.

## Training Method

At each interaction step, the agent selects a random action with probability
epsilon; otherwise, it selects the action with the highest predicted Q value.
Transitions are stored in a replay buffer and sampled randomly for training.

The Bellman target is:

```text
target = reward + gamma × (1 − terminated) × max_a Q_target(next_state, a)
```

The online network is optimized using Huber loss (`smooth_l1_loss`) and Adam.
Gradient norms are clipped to 10. The target network is periodically updated
from the online network. True termination disables bootstrapping; time-limit
truncation ends interaction without disabling bootstrapping.

The implementation supplied for this project uses these defaults. Confirm they
match your submitted source and any command-line overrides before submitting.

| Setting | Value |
|---|---|
| Training budget | 3,000,000 agent steps |
| Replay capacity | 50,000 transitions |
| Batch size | 32 |
| Discount factor | 0.99 |
| Learning rate | 0.0001 |
| Optimizer | Adam |
| Loss | Huber loss |
| Initial replay warm-up | 10,000 steps |
| Optimization frequency | Every 4 agent steps after warm-up |
| Target update frequency | Every 10,000 agent steps |
| Checkpoint frequency | Every 50,000 agent steps and at loop exit |
| Training epsilon | Linear decay from 1.0 to 0.1 over 1,000,000 steps |
| Evaluation epsilon | 0.01 |
| Random seed in agent | 595 |
| Evaluation environment seed | 11037 |

Agent steps refer to calls to the wrapped environment, rather than individual
emulator frames. The wrapper repeats actions over up to four emulator frames.

## Resume Training

The original 3,000,000-step run is complete. Additional training is optional.
To continue from the saved checkpoint toward 5,000,000 cumulative steps, set
the active Python command in `job.sh` to:

```bash
python -u main.py --train_dqn_again --total_steps 5000000
```

Then submit:

```bash
sbatch job.sh
```

`total_steps` is the cumulative stopping point. Starting from a 3,000,000-step
checkpoint, this requests 2,000,000 additional steps. Resume restores weights,
optimizer state, counters, and recent reward history. It starts a new game and
refills replay; it does not reproduce an uninterrupted run exactly.

Preserve the evaluated checkpoint before further training:

```bash
cp -p dqn.pth dqn_evaluated_280_55.pth
```
